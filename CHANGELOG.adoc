= changelog

== Unreleased

=== Fixed — memory safety

* *Thread-local storage is now scanned.* `markTLS` was guarded by
  `static if (__traits(compiles, { import rt.sections; ... }))`, which never
  succeeds in a normal build, so the whole body compiled away silently and any
  object reachable only from a thread-local global was freed while still live.
  TLS ranges are now scanned through druntime's per-thread `rt.tlsgc` handle.
* *Callee-saved registers are now scanned.* The mark phase scanned the stack
  without spilling registers first, so a pointer held only in a register — the
  norm in optimized builds — was invisible and its block was collected.
  Collection now runs inside `callWithStackShell`.
* *Payload alignment is 16 bytes*, as D requires. It was 8, which misaligns
  `real`, SIMD vectors and `align(16)` aggregates; an aligned SSE store into
  such a block faults on x86-64.
* *One-past-the-end pointers are honoured during marking.* D slices routinely
  materialise `ptr + length`; treating that as a non-reference freed live
  arrays. Exact lookups still reject it, so `GC.free(arr.ptr + arr.length)`
  cannot destroy a neighbouring block.
* *`GC.disable()` no longer suppresses an explicit `GC.collect()`.* It now
  suppresses only allocation-triggered collections, and nests as a counter.
* *A dying thread's memory is retained, not finalized and freed.*
  `cleanupThread` released every remaining block. `Thread.join()` propagates the
  child's `Throwable` to the parent *after* that cleanup runs, so the parent
  received a destructed object in freed memory — a use-after-free reachable from
  an ordinary `throw` inside a thread. Arenas are now adopted by a heap that no
  collection sweeps.
+
NOTE: This reverses an intermediate change made earlier in this same cycle,
which had `cleanupThread` *run* finalizers on the theory that thread exit is
analogous to program termination. It is not: the parent may still be about to
use those objects. See `CROSS-THREAD.md`.
* `cleanupThread` also tore the heap down before unregistering it, racing other
  threads' lookups; the order is now reversed.
* *`TypeInfo` is recorded at allocation* and passed to `rt_finalizeFromGC`, so
  struct finalizers can run. It was discarded and `null` was passed.
* *`realloc` no longer corrupts heap accounting.* Shrinking rewrote the stored
  block size without adjusting `usedBytes`, permanently skewing the collection
  trigger.
* *Cross-thread state is atomic.* `disabled` and the profiling counters were
  plain fields written from every thread.
* Collection on an unattached thread is refused rather than guessing a stack
  window, which could read unmapped memory.
* `removeRoot`/`removeRange` no longer `assert(false)` — that halted the
  process in release builds when removing an unknown root.
* `runFinalizers(segment)` is implemented instead of being a no-op.

=== Changed — performance

* *Precise scanning via `TypeInfo.rtInfo` pointer maps* (`tgcPreciseScanning`,
  on by default). Marking consults the compiler-emitted map for a block and
  probes only the words that can hold a reference: for a class with two
  reference fields among a vtable pointer and a monitor, half the words; for a
  class of mixed scalars and references, closer to a fifth.
+
Conservative in three places, deliberately. An unknown type scans everything;
`rtinfoHasPointers` -- what the compiler emits when it cannot describe a layout
-- scans everything; and an *appendable* block whose `TypeInfo` is a class
scans everything, because that is an array of references while the class's map
describes an instance. That last case is not hypothetical: `new C[8]` passes
the element class's `TypeInfo`, whose map for a pointer-free class reads "no
pointers" while the block is eight live references.
+
Binary-trees depth 18 went from 2.03 s to 1.95 s, depth 20 from 9.32 s to
8.79 s, and a 256k-object collection from 1.80 ms to 1.69 ms.

* *Allocation uses the bitmap instead of an intrusive free list*, and no longer
  zeroes every block. Profiling binary-trees put `freeSlot` at the top of the
  self-time histogram, ahead of marking: the free list was threaded through the
  free slots themselves, so every reclaimed object took a write into cold, dead
  memory. The allocation bitmap already records exactly the same information,
  so a free is now a cleared bit and nothing touches the payload; allocation
  finds the next clear bit from a per-chunk cursor.
+
Blocks are also only zeroed when `calloc` asks, matching druntime -- the
unconditional `memset` was clearing data the runtime overwrote immediately with
a type initialiser -- and the `disabled` check is ordered after the cheap
threshold test and relaxed to a raw atomic load.
+
Allocation went from 20.03 ns to 11.03 ns; binary-trees depth 18 from 2.29 s to
2.03 s and depth 20 from 10.35 s to 9.32 s.

* *Fiber enumeration walks the global context list once instead of twice*, with
  the cheap rejections first. Scanning was already restricted to the collecting
  thread's own fibers; finding them still means walking druntime's global list,
  because the ownership test must happen inside the thread lock -- once it is
  released another thread may destroy its fiber and unmap the stack.
+
Measured with each thread holding a constant 400 fibers, so all growth comes
from other threads': 8 threads went from 0.38 ms to 0.29 ms per collection, and
the curve flattened from 0.20-0.38 to 0.21-0.29. The residual growth is
inherent without a druntime change; see `IMPROVEMENTS.md`.

* *Heap growth now tapers as the heap grows*, capping headroom at
  `max(32 MiB, live * 2)` so the effective multiplier decays from 4 toward 3.
  The shape is borrowed from BEAM; its constants are not, because BEAM's
  per-process heaps are kilobytes and a +20% cap costs tgc 296 collections on a
  67 MB live set where this cap needs 76.
+
This corrects a claim made when the growth factor was introduced: that headroom
cannot lengthen a pause because mark-sweep costs time proportional to the live
set. Clearing marks and sweeping walk the whole heap, not just the live part, so
a bigger heap does lengthen every collection. Measured on binary-trees on an unloaded
machine, depth 18 / depth 20: flat x4 gave 2.82 s / 9.39 s using 96 MB / 448 MB;
the cap gives 2.25 s / 10.74 s using 48 MB / 128 MB, with max pause 23.8 ms
against 47.9 ms at depth 18. See `BEAM-NOTES.md`.

* *Heap growth factor is tunable* (`tgcHeapGrowth`, default 4).
  It was hardcoded at 2, which kept the heap at twice the live set and made tgc
  collect 135 times on binary-trees depth 18 where the conservative collector
  collected 7 -- 1.76 s of a 2.81 s run spent collecting. A mark-sweep pause
  costs time proportional to the live set rather than to the heap, so headroom
  reduces how *often* collections happen without lengthening any one of them:
  better for throughput and for pause count alike, at the cost of memory.

* *Slot state moved into per-chunk bitvectors.* `allocated`, `marked` and
  `shared` were fields of a 24-byte `SlotMeta` per slot, so clearing every mark
  meant a read-modify-write across all of it and the sweep touched 24 bytes to
  read one bit. They are now bitvectors, with attributes in a byte array;
  clearing marks is a `memset` over n/8 bytes and the sweep tests
  `allocated & ~marked & ~shared` 64 slots per word.
+
Per-slot metadata drops from 24 bytes to 17.375 -- measured as 48.50 to 41.94
bytes of arena per 16-byte object, 64.55 to 58.00 for 32-byte. Collection time
is unchanged (256k live objects: 1.83 ms), which is itself the finding: phase
timing shows conservative marking dominates at roughly 90% and sweeping was
already about 4%, so the SIMD-sweep win FUGC reports does not transfer. The
payoff here is density.
+
Prompted by FUGC; see `FUGC-NOTES.md`, which also records why soft handshakes
are *not* portable -- they need the same store barrier concurrent marking does.

* *Size classes extended to 32 KiB, and large blocks report their true size.*
  Any request between 8 KiB and 64 KiB previously fell through to a dedicated
  64 KiB chunk run, and both `GC.sizeOf` and the scanned range reported the
  whole run -- so a 9000-byte allocation occupied and scanned 65408 bytes, and
  every allocation zeroed all of it. HTTP-sized buffers land exactly there.
+
The bigger classes are served from multi-unit chunks so a chunk still holds at
least eight slots, and genuinely large blocks now record the requested size
rather than the rounded-up run.
+
[cols="1,1,1"]
|===
| | before | after

| 9000-byte request | 65408 B (7.3x) | 10240 B (1.1x)
| 4000 x 9000 B, memory | 249.6 MB | 39.1 MB
| 4000 x 9000 B, collect | 62.3 ms | 7.6 ms
|===
+
General collection scaling is unchanged (256k live objects: 1.85 ms). Prompted
by reading FUGC; see `FUGC-NOTES.md`.

* *Chunk-arena allocator.* Memory now comes from 64 KiB chunk-aligned arenas
  carved into size-class slots. A candidate pointer resolves to its block by
  masking and indexing instead of walking a linked list, so `markPtr`,
  `GC.free`, `GC.sizeOf` and `GC.addrOf` are all O(1).
* *Explicit mark worklist* replaces the rescan-until-stable fixpoint, which
  re-walked the entire heap once per pointer-graph level. Each live block is
  now scanned exactly once.
+
Measured collection time for a heap of N live 32-byte objects:
+
[cols="1,1,1"]
|===
| live objects | before | after

| 2,000  | 21 ms  | 0.05 ms
| 8,000  | 176 ms | 0.09 ms
| 16,000 | 577 ms | 0.15 ms
| 256,000 | (minutes) | 1.83 ms
|===
+
Scaling is now linear rather than quadratic.

* *Array API implemented* (`getArrayUsed`, `expandArrayUsed`,
  `reserveArrayCapacity`, `shrinkArrayUsed`, `extend`). These all returned a
  failure constant, which forced the runtime to reallocate and copy on *every*
  `arr ~= x`. Appending 100,000 elements went from 100,000 reallocations to 13.
* *The collection threshold decays.* It previously only ever grew, so a program
  that spiked once and then settled would never collect again.
* Fully empty chunks are returned to the allocator during sweep and
  `minimize()`; `stats().freeSize` reports real numbers instead of always `0`.
* Root and range tables are snapshotted under `rootsLock` and marked outside
  it. Marking under the lock made every other thread spin for the duration of
  a collection — a global pause in all but name.
* Pause time is measured: `profileStats()` reports `totalPauseTime` and
  `maxPauseTime`. `profilePauseTicks` was declared and never written.

=== Added

* `tgcMinHeap(size_t)` — a floor on a thread's collection threshold, the
  analogue of the default collector's `minPoolSize`. Without it a thread
  collects as soon as live data has grown by the growth factor, which for a
  small live set means collecting constantly; `minPoolSize:300` is why the
  default collector collects 7 times on binary-trees where tgc collected 64.
+
It is *per thread*, because tgc's heaps are, so matching a global pool of N
bytes across T threads means passing `N / T`. `bintree_mt.d` now does exactly
that, giving both collectors the same 300 MB total budget: tgc goes from 4983
collections to 27 at four workers, and from 2.171 s to 1.689 s.

* *Fiber-scoped regions* — `tgcBeginRegion` / `tgcEndRegion` / `tgcRunInRegion`,
  with `tgcRegionVerify` and `tgcRegionBytes`. Everything allocated while a
  region is open comes from chunks it owns exclusively, and closing it releases
  the lot without tracing: the BEAM model, where a process dies and its heap
  goes with it.
+
The payoff is not the sweep, which was already cheap; it is that request-scoped
memory never has to be *proved* dead, so it never enters the mark phase. A
handler loop allocating 200 blocks per request over 4000 requests:
+
[cols="1,1,1"]
|===
| | time | collections

| without a region | 58.5 ms | 799
| with a region | 36.3 ms | *0*
|===
+
Regions are bound to the running fiber rather than to thread-local state,
because fibers on a thread share TLS and a `yield` would otherwise route the
next fiber's allocations into the wrong region. Resolution is gated on a global
counter, so a program that never opens a region pays one predictable branch:
allocation is unchanged at 11.03 ns.
+
The precondition is BEAM's, without BEAM's enforcement. BEAM can free a dead
process's heap because every message is deep-copied on send; nothing here
copies, so *anything that must outlive a region has to be copied out of it* and
that is the caller's invariant. `tgcRegionVerify(true)` checks it dynamically at
every close — off by default because it costs a full mark — and is worth
enabling in test builds.

* `tgcCollectGlobal()` and `tgcGlobalThreshold(size_t)` — cooperative global
  collection, the only thing that can reclaim memory a thread-local collection
  cannot prove dead: arenas adopted from exited threads, and blocks promoted by
  escape tracking. Runs automatically once retained bytes pass the threshold
  (64 MiB by default; 0 disables it). `tgcRetainedBytes()` reports the figure it
  triggers on.
+
This is the one tgc operation that stops the world, and it stops it **for
marking only**: suspend, index every heap's chunks, mark from `thread_scanAll`
plus the global root tables, demote promoted blocks the mark proved unreachable,
resume. Reclamation happens afterwards -- the orphan heap is swept directly
since no thread owns it, and demoted blocks are freed by their owning thread's
next local collection, on that thread, so their finalizers run there.
+
Sweeping inside the stop was the first attempt and was wrong twice over: a
finalizer running with threads suspended can block on a lock one of them holds,
and freeing into a live thread's heap races that thread the moment it resumes.
Both showed up as intermittent failures before the restructure.
+
Measured: reclaiming 2 MB of arenas from eight exited threads takes a 0.07 ms
world-stop. Detached `@nogc` threads are still never paused, since
`thread_suspendAll` only suspends threads registered with the runtime.

* `tgcTrackEscapes(bool)` — opt-in escape promotion. A block observed reachable
  from a global root is promoted and never reclaimed by a thread-local
  collection, which closes the case of a block published to a global, picked up
  by another thread, then unpublished. Promotion is transitive and sticky, and
  already-promoted blocks are re-seeded as roots each cycle so their children
  are not swept out from under the thread holding them.
+
**Off by default.** Because the promoted set never shrinks it must be
re-scanned every cycle; on a workload publishing and dropping 50,000 objects
repeatedly the mark phase grew from 0.25 ms to 3.66 ms as the set reached
212,000 blocks, and would keep growing. For a collector whose value is bounded
pause time that is a worse failure than the bug it fixes, so the caller decides.
With it off, collection times are unchanged.
+
Two limits remain, both documented in `CROSS-THREAD.md`: promotion is *sampled*
at collection time, so a block published and unpublished entirely between two
collections is never seen; and promoted blocks accumulate until a cooperative
global collection exists to reclaim them.

=== Fixed — found by ThreadSanitizer

* *Use-after-free in `test/tgc_region.d`*, which queried a region handle after
  `tgcEndRegion` had freed it.
* *Three locks released immediately instead of on scope exit.* Introduced while
  adding the TSan annotations: `scope (exit) tsanRelease(...); lock.unlock();`
  binds only the first statement to the guard, so the unlock ran straight away.
  This affected `collectGlobal`'s hold on `heapsLock` and two `orphanLock`
  sites. TSan caught it immediately -- the races it had stopped reporting came
  back the moment the bug appeared.
* Two scan routines (`markRange`, `markRootsAndRanges`) had silently lost their
  sanitizer exemption in an earlier refactor.

=== Infrastructure

* Converted `AGENTS.md`, `README.adoc`, `LICENSE`, `.gitignore`,
  `source/tgc/package.d`, `source/tgc/gcobj.d` and the publish workflow from
  BOM-less UTF-16LE to UTF-8. The workflow was unparseable YAML, so the publish
  pipeline could not run, and `.gitignore` matched nothing.
* Added `.gitattributes` enforcing UTF-8 and LF.
* Added a CI workflow: DMD and LDC across Linux/macOS/Windows, an encoding
  guard, and AddressSanitizer/ThreadSanitizer jobs. Both sanitizers have now
  been run against the collector on Linux/x86-64 and report nothing: TSan zero
  warnings across three consecutive runs, ASan zero errors. They remain
  unrunnable on macOS/arm64, where both runtimes fail on a bare
  `printf("hello")`.
* tgc's spinlock-guarded structures carry `__tsan_acquire`/`__tsan_release`
  annotations rather than suppressions, because TSan cannot see through
  druntime's `SpinLock` -- verified with a four-thread counter that is exact
  under the lock yet still reported as racing. Annotating keeps those
  structures checked. The world-stopped section of a global collection is
  wrapped in `__tsan_ignore_thread_begin/end`, since suspension is a signal
  handshake TSan cannot model. `.tsan-suppressions` covers only druntime's own
  `thread_suspendHandler`, which does not preserve `errno`.
* Added `test/tgc_safety.d`, an adversarial suite covering reachability
  (TLS-only, `__gshared`-only, `addRoot`-only, interior and one-past-the-end
  pointers), alignment, reclamation, `disable()` semantics, finalization at
  thread exit, concurrent collection and array append. The previous smoke test
  passed identically under `--DRT-gcopt=gc:conservative`, so it could not
  detect either a failure to select tgc or tgc freeing live memory.
* Added `test/tgc_stress.d`: pattern-checked allocator stress covering
  size-class edges, the small/large chunk transition, chunk release and reuse,
  explicit `free`, `realloc` across boundaries, concurrent churn and repeated
  thread teardown.
* Added a `unittest-optimized` build type; the unoptimized default hides
  register-held pointers and dead-store elimination.
* Mark routines are annotated `@noSanitize("address")` under LDC: conservative
  scanning reads padding, redzones and quarantined memory by design, so those
  reads must not be reported. Test iteration counts scale down under
  `version(TgcSanitize)`.

* *Fiber stacks are scanned.* `thread_stackBottom()` reports only the running
  `StackContext`, so the collector saw exactly one stack: a collection triggered
  inside a fiber missed the thread's own stack *and* every other suspended
  fiber, freeing their live data. Since allocation triggers collection and, in a
  fiber-based program, allocation happens inside fibers, this was the common
  case rather than a corner case. tgc now walks druntime's global
  `ThreadBase.sm_cbeg` context list — the same list the stop-the-world collector
  uses — scanning each context's *used* span `[tstack, bstack)`.
+
Measured cost, 50,000 live objects:
+
[cols="1,1"]
|===
| suspended fibers | collect

| 0      | 0.32 ms
| 1,000  | 0.64 ms
| 10,000 | 3.55 ms
|===
+
About 0.32 µs per suspended fiber. Known limitation: the context list is global,
so every thread scans every other thread's fibers. druntime records no
fiber-to-thread affinity, so narrowing this needs tgc-side tracking.

* *Fiber scanning is restricted to the collecting thread's own stacks.* Walking
  druntime's global context list wholesale could fault: another thread may
  destroy a fiber and unmap its stack while we read it, which showed up as an
  intermittent segfault in the multi-threaded fiber test. It was also wasteful,
  since a thread can only mark blocks in its own heap. A thread's own contexts
  are now identified by the active `m_curr`/`within` chain plus, for suspended
  fibers, whether this heap owns the `StackContext` block that `Fiber` allocates
  with `new` on its creating thread.

* *Removed a cross-thread data race in `queryBlock`.* Looking up a pointer this
  thread does not own used to probe every other live thread's chunk map under
  `heapsLock`, while those maps are mutated by their owners under no lock at all
  -- and `ChunkMap.grow` frees the old key and value arrays. That is a
  concurrent read of freed memory, reachable from an ordinary `GC.sizeOf`. The
  fallback now searches only the orphan heap, which is mutated exclusively under
  `orphanLock`; another live thread's heap is never touched.
+
Found by inspection, not by a test. It resisted reproduction even with a 200 us
delay injected into `ChunkMap.grow` and 400,000 concurrent cross-heap queries,
because a reader of a just-freed malloc block usually gets stale-but-plausible
data rather than a fault. `test/tgc_race.d` covers the path but does not detect
the original bug -- confirmed by running it against the pre-fix commit.

* *Removed the remote free queue.* With the cross-heap lookup gone, `free()` can
  no longer resolve another live thread's block, so the queue was unreachable
  code that implied a supported ownership-transfer path. Removing it also drops
  a call from every allocation.

* Cross-thread tuning state (`escapeTracking`, `globalThreshold`,
  `orphanBytes`) is now atomic; it was plain `__gshared` read and written from
  several threads.

* Fixed the CI sanitizer job, which could never have run: it passed
  `--dflags=...` to `dub test`, which dub rejects. The flags now live in
  `unittest-tsan` and `unittest-asan` build types.

* *`GC.extend` claimed extensions it never performed — memory corruption.*
  The contract is "enlarge the block by at least `minsize` *additional* bytes;
  a non-zero return is the new total size". tgc read it as "is the block already
  at least `minsize`", and returned the capacity whenever it looked big enough.
  The runtime then believed the block had grown and wrote past the end of the
  slot into its neighbour, corrupting the free-list pointer threaded through
  free slots. A slot has a fixed size and cannot grow, so the only correct
  answer is 0; in-place array growth goes through `expandArrayUsed`, which
  checks against the real capacity.
+
Present since the arena landed, and missed by the entire test suite. It was
found by running the binary-trees benchmark, which crashed with SIGBUS on any
program that combined a live linked structure with phobos string formatting.
Regression tests added in `test/tgc_stress.d` cover both `GC.extend`'s contract
and the formatting-plus-live-structure pattern; both fail against the previous
commit.

=== Fixed — found during this work

* Use-after-free in the sweep: freeing the single slot of a large chunk
  releases the chunk, but the loop then re-read `slotCount`/`freeCount` from
  the freed header.
* A finalizer that allocates could be handed a slot from the chunk being swept,
  at an index the sweep had not yet reached, and that fresh object was then
  immediately freed by the same sweep. Allocation now marks blocks black while
  a collection is in flight.

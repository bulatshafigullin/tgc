= tgc

Opt-in **thread-local garbage collector** for D (`tgc`). Each attached thread owns a private heap arena; collection on one thread does not stop-the-world pause sibling threads or detached `@nogc` workers.

Informal name: realtime GC. Registered runtime name: `tgc`.

Part of link:https://github.com/dlang-supplemental[dlang-supplemental]. Design write-up: link:https://dlang-supplemental.github.io/docs/docs/blog/thread-local-gc-tgc.html[Thread-local GC (tgc) for D].

== Install

[source,powershell]
----
dub add tgc
----

== Enable

Import the hook module so the factory is linked, then select the collector:

[source,d]
----
import tgc.gcobj;

// Option A — runtime flag
// ./app --DRT-gcopt=gc:tgc

// Option B — default at link time (add versions "Tgc_default" to your dub config)
extern(C) __gshared rt_options = ["gcopt=gc:tgc"];
----

== Requirements

* DMD 2.112+ or LDC with pluggable GC + `registerGCFactory` thread init hook (same era as SymGC integration).
* Prefer message passing / ownership transfer across threads; unrestricted shared mutable GC pointers are unsupported in v1.

== Design

Each thread allocates from private 64 KiB chunk-aligned arenas carved into
size-class slots. Because chunks are aligned to their own size, a candidate
pointer is resolved to its block by masking and indexing rather than by
searching, so marking, `GC.free` and `GC.sizeOf` are all constant time. The
mark phase uses an explicit worklist, visiting each live block exactly once.

A collection scans only the collecting thread's stack, callee-saved registers,
TLS and the shared root/range tables. `thread_suspendAll` is never called, and
the root tables are snapshotted rather than held locked for the duration.

=== Limitations

* *Cross-thread sharing is unsupported in v1.* A block handed to another thread
  is still owned by the allocating thread's heap, and that heap's collector
  never scans the other thread's stack, so the block can be swept while still in
  use. Prefer `immutable` or copied message passing.
+
`tgcTrackEscapes(true)` opts into retaining anything seen reachable from a
global, which covers the common publish-to-a-global handoff. It is off by
default: the retained set never shrinks and is re-scanned every cycle, so pauses
grow with everything the program has ever published. See
link:CROSS-THREAD.md[CROSS-THREAD.md] for why D's type system cannot settle this
at allocation time, and what can.
* *A thread's memory is not reclaimed when it exits.* Its arenas are retained,
  because `Thread.join()` hands the parent objects the child allocated. Suited
  to a fixed worker pool; unsuitable for programs spawning many short-lived
  threads.
* `GC.collect()` collects only the calling thread's heap. A thread that never
  allocates never collects.
* Marking is conservative; no precise scanning or moving/compaction.

Fibers are supported: every registered stack context is scanned, not just the
running one. Building a server on this? See link:WEBSERVER.md[WEBSERVER.md].

= tgc

Opt-in **thread-local garbage collector** for D (`tgc`). Each attached thread owns a private heap arena; collection on one thread does not stop-the-world pause sibling threads or detached `@nogc` workers.

Informal name: realtime GC. Registered runtime name: `tgc`.

Part of link:https://github.com/dlang-supplemental[dlang-supplemental]. Design write-up: link:https://dlang-supplemental.github.io/docs/docs/blog/thread-local-gc-tgc.html[Thread-local GC (tgc) for D].

== Install

[source,powershell]
----
dub add tgc
----

== Enable

Import the hook module so the factory is linked, then select the collector:

[source,d]
----
import tgc.gcobj;

// Option A — runtime flag
// ./app --DRT-gcopt=gc:tgc

// Option B — default at link time (add versions "Tgc_default" to your dub config)
extern(C) __gshared rt_options = ["gcopt=gc:tgc"];
----

== Requirements

* DMD 2.112+ or LDC with pluggable GC + `registerGCFactory` thread init hook (same era as SymGC integration).
* Pass data across threads by copying or by `immutable`; heaps are strictly thread-private, and a GC block belongs to the thread that allocated it.

== Design

Each thread allocates from private 64 KiB chunk-aligned arenas carved into
size-class slots, themselves carved from a few large huge-page-aligned mappings
rather than from `malloc` -- on Linux that is worth an order of magnitude in
pause time, because a per-chunk heap can never be backed by huge pages. Because chunks are aligned to their own size, a candidate
pointer is resolved to its block by masking and indexing rather than by
searching, so marking, `GC.free` and `GC.sizeOf` are all constant time. The
mark phase uses an explicit worklist, visiting each live block exactly once.

A collection scans only the collecting thread's stack, callee-saved registers,
TLS and the shared root/range tables. `thread_suspendAll` is never called, and
the root tables are snapshotted rather than held locked for the duration.

=== Limitations

* *Heaps are strictly thread-private.* A block handed to another thread is
  still owned by the allocating thread's heap, and that heap's collector never
  scans the other thread's stack, so the block can be swept while still in use.
  Pass ownership by copying or by `immutable`, not by pointer.
+
Misuse is now detected rather than silent: `GC.free`, `realloc`, `setAttr` and
the array-mutating calls assert when handed a block belonging to another
thread's heap. Read-only queries such as `GC.sizeOf` stay quiet and answer
"no block", because callers ask those speculatively. The checks are asserts, so
a `-release` build is silent again; build with `-version=TgcEnforce` to keep
them, which costs two atomic loads on a path a correct program never takes and
turns a development aid into a guarantee.
+
`tgcTrackEscapes(true)` opts into retaining anything seen reachable from a
global, which covers the common publish-to-a-global handoff. It is off by
default: the retained set never shrinks and is re-scanned every cycle, so pauses
grow with everything the program has ever published. See
link:CROSS-THREAD.md[CROSS-THREAD.md] for why D's type system cannot settle this
at allocation time, and what can.
* *A thread's memory is not reclaimed when it exits* by a thread-local
  collection, because `Thread.join()` hands the parent objects the child
  allocated. It is reclaimed by the next global collection, which runs
  automatically once retained bytes pass `tgcGlobalThreshold` (64 MiB), or on
  demand via `tgcCollectGlobal()`. That is the only tgc operation that stops the
  world; it stops it for marking only, measured at 0.07 ms for 2 MB of adopted
  arenas.
* `GC.collect()` collects only the calling thread's heap. A thread that never
  allocates never collects.
* Marking is conservative; no precise scanning or moving/compaction.

Memory is returned to the OS without being asked: a collection compares
committed bytes against peak demand over the preceding half-second and, past
`tgcTrimRatio` (2 by default), hands back every 2 MB span holding nothing.
`GC.minimize()` still exists for "give it back now" and ignores both the ratio
and the one-segment floor. `GC.reserve(n)` maps and faults in `n` bytes up
front, so a latency-sensitive caller pays for the pages before its first
request rather than inside it.

Fibers are supported: every registered stack context is scanned, not just the
running one. Building a server on this? See link:WEBSERVER.md[WEBSERVER.md].
